# Hooks v2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans
> to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** user-configurable hook commands on harness events — `post_tool_use`
(result rewriting) and `on_turn_end` (observe-only); fail-open, timeout,
one command per event.

**Spec:** docs/superpowers/specs/2026-11-18-hooks-design.md

## Global Constraints

- Fail-open always: a broken hook never breaks a turn.
- No built-in hook logic in the binary — only the runner.
- `cargo clippy -- -D warnings` + `cargo fmt --check` + workspace green per task.
- Conventional commits; standing consent for main commits; push on "continue".

## Review Focus

- Timeout semantics: does a hung hook actually free its slot (process killed, not just abandoned)?
- Deadlock: hook spawns while the loop holds the sessions lock.
- JSON contract drift: what the hook returns vs what the loop consumes.
- Non-UTF8 hook output (lossy conversion, never a panic).
- Rewriting a tool result that is later persisted — transcript must carry the REWRITTEN text (the model never sees the original), while stderr keeps the original for debugging.
